## 1. 什么是体系结构

| 定义 | 关注什么 | 以 CPU 的 `lw` 指令为例 |
|---|---|---|
| **狭义的体系结构** | 软件可见的硬件行为，包括指令语义、寄存器、寻址方式、异常和内存模型。对 CPU 而言，核心是 **ISA（指令集架构）**。 | `lw` 如何计算地址、读取多少位、结果写到哪个寄存器。 |
| **广义的体系结构** | 计算机系统如何组织和实现，涵盖 ISA、处理器微架构、存储层次和系统互联。 | `lw` 在哪一级计算地址、如何访问 Cache、数据回来前能否先执行其他指令。 |

体系结构存在的目的就是为了：**针对特定工作负载，在面积、功耗和成本等约束下，组织计算、存储和通信资源，让系统达到目标性能**

> 20261116: 作为初学者，学着先，慢慢摸索体系结构的整体框架，暂时从广义定义出发来记录，也就是ISA和微架构两个方面

## 2. ISA

### 2.1 什么是ISA

ISA（Instruction Set Architecture，指令集架构），他的目的是让硬件理解当前该做什么。

程序的实现思路是将一个动作或者事件划分为多个小事件，每一个事件的执行结果影响下一事件的执行，最终得到想要的计算结果或者判断，这些小事件的递归拆分最终体现为指令。

ISA通过约定指令的结构以及内容来让硬件明白当前阶段该执行什么操作。硬件则根据微架构进行设计，微架构决定硬件在哪个周期、哪个流水级执行这些操作，以及如何处理指令间的依赖。

ISA的设计决定了软件实现的复杂度。对于软件而言，ISA设计直接体现为指令颗粒度，也即一条指令能够控制到什么程度，颗粒度越粗则软件能控制的东西越宏观，反之则越底层。对于硬件而言，ISA设计体现为字段结构以及功能划分，这些因素影响硬件设计时的具体功能划分

### 2.2 ISA发展历程

| 时期 | 代表 | 当时要解决的问题 |
|---|---|---|
| **1960 年代：统一软件接口** | IBM System/360 | 让不同档次、不同硬件实现的机器运行兼容的软件，降低换机器时的软件迁移成本。([IBM][1]) |
| **1970 年代：指令功能趋于丰富** | 早期 x86、VAX | 一条指令可以表达更复杂的操作，减少程序需要的指令条数。代价是硬件要处理更多指令格式、寻址方式和执行情况。([people.eecs.berkeley.edu][2]) |
| **1980 年代：RISC 兴起** | Berkeley RISC、Arm | 让常用指令更规整。例如，普通算术指令只操作寄存器，访存交给 `load/store`。这样更容易做译码和流水线，复杂操作可以由编译器组合。([people.eecs.berkeley.edu][3]) |
| **2010 年以来：开放、模块化的代表** | RISC-V | 提供开放的基础指令集，按需求加入标准扩展。例如，`RV32I` 提供基本整数指令，加上 `M` 就得到乘除法指令。([RISC-V International][4]) |

首先是第一阶段，ISA诞生。当时IBM为了适配不同应用场景，分别开发了不同机器来执行对应功能，但随着版本演进，不同机器的代码发展路线不同，无法彼此兼容。出于同一机器码可以在不同机器上执行的思想，IBM推出了统一指令接口，所有软件于硬件通过相同的接口进行转换，这样子就可以实现机器码的兼容。

接下来是第二阶段（1979年），当时的内存非常的昂贵，同一功能实现需要越多的指令就会消耗越多的内存，也即成本越高。因此当时的优化方向是减少同一功能实现所需要的指令数量，最终表现为指令能够实现的功能多样性。

另一方面，提升性能是贯穿体系结构发展的主线，因此除了优化内存占用量外，有的厂商选择提升位宽以提高性能。这一方向将初代统一指令接口的8bit位宽提升为16bit位宽，同时保留对此前的软件兼容性，也就是X86架构。

> 初版x86就是intel 8086，但很快下一版8088就将外部16bit总线改回8bit总线，原因是当时绝大多数设备的外部总线还是8bit，将总线位宽从16bit降低至8bit虽然会减少外部访存能力，但可以有效降低整机成本（复用此前硬件）

再然后的第三阶段（1985年），此时各厂商都在尝试提升总线位宽，位宽从16bit提升到32bit；intel推出32位版本80386，同年arm推出arm1。80386凭借ibm pc占据了大型机的生态，arm1则凭借低功耗的特性在手机市场普及，此时pc/mobile两界主流框架就定型了下来。

接着是位宽提升到64bit的第四阶段（2003年），amd推出opteron，首次推出amd64，将x86扩展至64位。intel则迟了一年才推出64位版本，也就是em64t。

64位也是目前的最大位宽了，arm在2011年发布了其64位版本，直到13年才有苹果首先应用到手机（64位A7，iphone 5s）

在此之间，由于x86架构的臃肿指令集，伯克利于2010年推出了简化指令集RISC-V的首版公开规范，兼容32位和64位。但直到2019年才通过RV32I、RV564I的基础规范。

整个isa的发展历程如下表所示：

| 时间 | 代表事件 | 当时的目的 |
|---|---|---|
| **1952–1953** | **IBM 701** 公布并交付 | 用电子计算机加速耗时的科学与国防计算。([ibm.com][1]) |
| **1959** | **IBM 1401 与 7090** | 按用途分别设计。1401 面向账务、报表等商业数据处理，7090 面向科学计算。不同产品线的机器码难以直接通用。([ibm.com][2]) |
| **1964** | **IBM System/360** | 让不同档次的机器共享一套软件可见的架构，使客户升级硬件时能继续使用已有程序。([www.ibm.com][3]) |
| **1970–1972** | **IBM System/370** 推出，随后加入虚拟内存 | 延续 System/360 的软件兼容性，同时让程序使用比实际物理内存更大的地址空间。([IBM][4]) |
| **1976** | **Cray-1** 向量超算 | 用一条向量指令对多个元素做同一种运算，提高科学计算的吞吐量。([museum.ipsj.or.jp][5]) |
| **1977** | **DEC VAX-11/780** 公布 | 突破 PDP-11 的地址空间限制，同时用较复杂的指令直接表达函数调用、循环等常见操作。([archive.computerhistory.org][6]) |
| **1978–1979** | **Intel 8086、8088** 推出 | 8086 提供完整的 16 位运算和 1 MiB 寻址。8088 沿用其指令集，把外部数据总线缩为 8 位，以复用现有器件、降低整机成本。([stevemorse.org][7]) |
| **1970 年代至 1980** | **IBM 801** 研究项目，1980 年做出原型 | 用规整的常用指令配合编译器，提高执行效率。这是早期 RISC 路线的代表。([www.ibm.com][8]) |
| **1981** | **IBM PC** 采用 8088 | 采用已有的处理器和配套器件搭建个人电脑。IBM PC 的普及随后带动了 x86 软件生态。([www.intel.com][9]) |
| **1982–1985** | **80286 → 80386** | 80286 延续 16 位 x86，80386 将 x86 扩展到 **32 位**，支持更大的地址空间。([www.intel.com][10]) |
| **1985–1990 年代** | **ARM1** 问世，Arm 随后进入手机市场 | Acorn 最初为自家电脑设计易于实现的 **32 位 RISC** 处理器。后来低功耗适合手机，IP 授权让其他厂商能将 Arm 核集成进自己的芯片。([documentation-service.arm.com][11]) |
| **2003–2004** | **AMD64 → Intel EM64T** | AMD 先把 x86 扩展到 **64 位**，同时保留对已有 32 位应用的支持。Intel 随后推出兼容实现，后来称为 Intel 64。([ir.amd.com][12]) |
| **2010–2011** | **RISC-V** 启动并发布首版公开规范 | 为研究和教学提供开放、易于实现和扩展的 ISA。首版就考虑了 **32 位和 64 位**两种变体。([riscv.org][13]) |
| **2011–2013** | **Armv8-A** 公布，随后苹果推出 **A7** | Armv8-A 引入 **AArch64**，扩展了寄存器和寻址能力。A7 将 64 位 Arm 带入消费级智能手机。([support.arm.com][14]) |
| **2019–2024** | **RISC-V 基础规范获批，随后推出 RVA23** | 先稳定 `RV32I`、`RV64I` 等基础指令集，再为应用处理器约定一组共同扩展，让操作系统和二进制软件更容易跨不同芯片运行。([docs.riscv.org][15]) |
